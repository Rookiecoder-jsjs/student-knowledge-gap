# 页面设计稿（教师端 Web）

依据：`docs/DESIGN.md` §5/§9/§13 + `api-inventory.md`。
目标用户：单班数学教师，高频场景是**考后 48 小时内**完成录入→讲评准备。

## 0. 信息架构

```
教师工作台（左侧一级导航）
├── 班级概览        ← 默认落地页：进度环 + 最近考试 + 待办（审核/提交）
├── 考试录入        ← 最高频链路：采集 → 审核 → 提交
├── 学生诊断        ← 个体薄弱点 + 归因（价值兑现第 2/3 阶）
└── 质量分析        ← 班级共性报告（价值兑现第 1 阶）
设置（知识库 / 班级名单 / 教学进度）     ← 低频，向导完成后很少进
```

首次使用无数据时，落地页直接引导进**首次使用向导**（全屏步骤流，完成后不再出现）。

全局规范：
- 任何列表**不按总分排序**学生（双减硬约束）；学生选择器按名单原序/拼音。
- 所有薄弱/归因展示必须携带证据入口（题数、最近时间、置信度）。
- 空/加载/错误三态全页面覆盖；错误态给重试按钮而非空文案。
- AI 生成内容统一灰色标签"模型生成"，且教师预览后才可导出。

## 1. 首次使用向导（3 步）

冷启动关键：不补齐历史数据，薄弱判定会全是"数据不足"。

```
┌────────────────────────────────────────────────┐
│  ① 导入知识库 ──── ② 建班与名单 ──── ③ 教学进度 │
│                                                │
│  [③ 教学进度]                                   │
│  已教章节（勾选知识点树）：        教授日期 [____] │
│   第一章 有理数  ▾  ☑全部                       │
│   第二章 整式    ▾  ☑全部                       │
│   第三章 一元一次方程 ▸                          │
│                                                │
│  提示：勾选"已教"后，未教知识点不会误判为薄弱      │
│                              [上一步] [完成设置] │
└────────────────────────────────────────────────┘
```

- 第 1 步：`POST /kb/upload`（浏览器上传 YAML）；部署预置了知识库时也可直接调 `POST /kb/import` 传路径。
- 第 2 步：`POST /schools` → `POST /schools/{id}/classes`，名单支持粘贴多行文本逐行解析（教师习惯从 Excel 复制）。
- 第 3 步：`POST /classes/{id}/progress`，知识点树按章节折叠，批量勾选。
- 结束态：引导"补录 2~3 次历史考试"（跳考试录入页，type=补录）。

## 2. 考试录入（入口页）

```
┌──────────────────────────────────────────┐
│ 新建考试                                  │
│  名称 [________]  日期 [____]  类型 [单元 ▾] │
│                                          │
│  ┌─ 拍照录入（推荐）─┐ ┌─ Excel 成绩表 ─┐ │
│  │ 上传空白试卷照片   │ │ 已有模板+分数表 │ │
│  │ AI 解析题目与标注  │ │               │ │
│  └────────────────┘ └──────────────┘  │
│                                          │
│ 最近考试（待办角标：待审核/未提交）         │
│  · 10月月考   已提交                      │
│  · 期中考试   待审核 3 题        [去审核]  │
└──────────────────────────────────────────┘
```

- 拍照路径：`POST /exams/photo-template`（multipart）。返回后弹**解析结果摘要**：题数、`warnings[]`（闭集丢弃、补标注提醒，琥珀色列表），主按钮"去审核标注"。
- 解析中 loading 态明确（LLM 调用约数秒至十几秒），禁用重复提交。
- Excel 路径：先 `POST /exams` 建模板（或复用已有），再 `POST /exams/{id}/import-excel`；结果页三栏：成功导入数 / **未匹配学生（红色，逐个列出并给"手工补录"入口）** / 警告。
- 列表数据源：`GET /exams?class_id=`（`unreviewed_tags>0` 渲染"去审核"角标）。

## 3. 审核台（左图右表）

```
┌───────────────┬─────────────────────────────┐
│  试卷扫描图    │ 题1 · 选择 · 5分      置信 0.92│
│ （可缩放）     │  题干：下列关于绝对值…          │
│               │  标注：[M7A-105 绝对值 ×] [+改] │
│   点击题号     │ 题2 · 解答 · 10分     置信 0.55 │
│   定位到题     │  标注：[M7A-111 ×]             │
│               │  ⚠ 低置信，请确认               │
│               │ ……                             │
│               │ [全部批准标注]（需逐题过目后启用）│
└───────────────┴─────────────────────────────┘
```

- 数据源：`GET /exams/{id}`（P0 缺口，回显模板）+ `GET /exams/{id}/review-queue`。
- 异常式审核：高置信题默认折叠，只展开低置信与未审项；顶部计数"需人工 3 题"。
- 改标交互：知识点选择器只允许闭集（KB 内编码可搜索），支持一题多知识点权重分配。
- 落闸：`POST /exams/{id}/approve-tags`；逐题修改用 `PATCH /template-questions/{qid}/tags`（改后自动视为已审核）。
- 审核完成后浮出下一步引导："采集学生卷"。

## 4. 学生卷采集

```
┌─────────────────────────────────────────────┐
│ 期中考试 · 采集进度      已提交 28/45         │
│ 状态：○未采集 ◐待审核 ●已提交                 │
│                                             │
│ 学生    状态   得分    操作                   │
│ 张*一   ●     87     [查看]                 │
│ 李*二   ◐     72     [核对低置信]            │
│ 王*三   ○      —     [拍照] [手工录入]        │
└─────────────────────────────────────────────┘
```

- 名单原序，不按分数排序。
- 拍照：`POST /exams/{id}/photo-response`（后端已做姓名栏遮盖，界面无需处理但应在文案说明隐私保护）。
- 手工录入：单生分数网格（题号列 + 得分输入），前端即时校验越界（超满分标红），提交 `POST /exams/{id}/manual`；后端整单拒绝时把具体越界题定位到输入框。
- 低置信得分修正：`PATCH /response-answers/{aid}`（仅待审核状态可改，改后退出低置信队列）。
- 进度矩阵：`GET /exams/{id}/responses`（summary 计数 + 每生 status/low_confidence_count 角标）。

## 5. 提交与结果反馈

- `POST /exams/{id}/commit`，二次确认弹窗："提交后数据进入分析，后续仅可通过补录追加"。
- 结果页展示：提交人数、**派生证据条数**（正向反馈，让教师理解数据去向）、skipped 明细（琥珀色）。
- 提交成功 → 双 CTA："生成班级质量分析" / "继续采集下一场"。

## 6. 班级质量分析

```
┌──────────────────────────────────────────┐
│ 考试选择 [期中考试 ▾]    [AI 解读 关 ▸开]   │
│                                          │
│ （Markdown 渲染区：共性薄弱点、讲评建议、   │
│   各题得分率……数字全部来自系统计算）        │
│                                          │
│ 若开启 AI 解读：                          │
│ ┌ AI 解读（模型生成）──────────────┐      │
│ │ ……                        [预览] │      │
│ └────────────────────────────────┘      │
│                        [复制] [导出 .md]  │
└──────────────────────────────────────────┘
```

- `GET /classes/{id}/quality-report?exam_id=&narrative=`。
- narrative 开关默认关；开启时解读段带"模型生成"标签，**导出前强制教师预览确认**（合规硬约束）。
- 待审核数据可出"初步报告"，页首显著横幅标注"含未审核数据"。

## 7. 学生诊断单

```
┌──────────────────────────────────────────┐
│ 学生选择 [王*三 ▾]（名单原序）  as_of [今天] │
│                                          │
│ ① 进步区：较上次提升的知识点（先呈现）       │
│ ② 薄弱点卡片（可展开）：                    │
│    M7A-114 一元一次方程应用    掌握度 0.42  │
│    判据：绝对底线+班级P25  证据 5题  轨迹↘   │
│    ▸ 归因假设：前置缺陷 → M6-02（置信 高）   │
│        [查看证据链]  [不认可？填备注]        │
│ ③ 数据说明：未学到 X 项 / 数据不足 Y 项     │
└──────────────────────────────────────────┘
```

- 渲染 `GET /students/{id}/diagnosis`（markdown），结构化数据辅助来自 `GET /students/{id}/weaknesses`（判据/证据数/轨迹直接映射卡片字段）。
- 归因卡片三种类型差异化图标与措辞：前置缺陷（给补基建议）、遗忘衰减（给复习建议）、数据不足（明确"暂不判定"）。
- **教师否决**：每张归因卡的"不认可+备注"入口 → `POST /attributions/{id}/override`（已实现；被否决归因在引擎重跑时永不复活）。
- 措辞成长框架：先进步后缺口，禁用"差/落后"。

## 8. 掌握度画像（探索性，最低优先级）

- `GET /students/{id}/mastery?as_of=`，按章节分组的掌握度网格（色阶仅表达高低，不做学生间比较），日期滑块回看。

## 实现备注

- 选型建议：教师端 Web 优先（桌面审核台需要左图右表宽屏）；学生/家长端若做再评估小程序（DESIGN §16 未决）。
- Markdown 渲染需支持表格与加粗；AI 解读段按标题识别（`## AI 解读（模型生成，数字以上文系统计算为准）`）套专属样式。
- multipart 上传（photo-template / photo-response / import-excel）前端统一封装，带进度条与超时重试。
