# 可靠性与教师优先事项

## 目标与范围

教师打开班级工作台后，先看到需要复核的数据和待确认的教学建议，明确依据及下一步入口。沿用现有诊断单作为行动确认的唯一编辑入口；首页展示前三项和结果摘要。

## 数据来源与字典

| 来源 | 粒度与刷新 | 字段 | 含义与用途 |
| --- | --- | --- | --- |
| 班级考试摘要 | 每场考试；打开工作台加载最近 6 场 | exam_id、unreviewed_tags、response_counts | 定位需要复核的标注或学生作答；链接对应审核／采集页 |
| 班级行动队列 | 后端折叠排序后的前 10 条；打开页面加载 | id、scope、kp_name、kind、note、group_size、alias | 说明建议对象、知识点、处理原因；复用后端优先级 |
| 行动队列汇总 | 全量待确认建议 | pending_confirm | “全部行动”入口计数，不用前三项数量代替总积压 |
| 干预结果汇总 | 可评估干预及待复测干预 | effects.improved、evaluable_count、effects.awaiting_retest | 展示改善数量、有效分母及等待状态，不把无复测当无改善 |

## 排序和页面逻辑

1. 最近 6 场考试中待审核标注／作答优先，因为未复核数据会影响后续诊断。
2. 其次按现有后端行动队列顺序展示教学建议，不重新计算诊断分数。
3. 首页最多展示 3 项，并明确数据范围；链接到全部考试和班级诊断单。
4. 数据加载或失败时保留加载／重试状态，不把失败当作“没有待办”。
5. 复测结果只陈述观测到的改善，不作因果效果承诺。

## 可靠性实现与边界

- 任务读取和重试复用班级／考试的权限裁决，未知类型及孤儿任务拒绝访问；内部异常详情只在受控日志中保留。
- 拍照接口以类型化联合响应区分同步结果与入队结果；OpenAPI 子集和 TypeScript 类型由脚本生成并在 CI 校验。
- 拍照页面 URL 的 `photo_job`／`batch_job` 保留任务编号，刷新恢复查询，每次查询重新鉴权；失败显式重试，网络故障退避重连。隐藏进度不会取消服务器任务。
- Worker 每 30 秒续租；租约 10 分钟。所有完成／失败／续租更新校验执行者与单调递增的尝试号。内置任务的业务数据和成功结果一起提交。SQLite 长写事务可能阻塞独立心跳；完成更新允许尚未被新尝试接管的原执行者提交，已被接管的执行者仍会回滚。
- 外部副作用仍须自行幂等：报告成功后的网关触发依赖现有幂等键；此改动不承诺跨数据库与外部 HTTP 的恰好一次投递。
- SQLite 仍用于单进程。多实例需要 PostgreSQL，不能用新增租约逻辑替代部署限制。
- 浏览器回归使用临时数据库、真实登录与业务 API，模型为固定响应；网络中断／失败重试测试使用明确的接口替身。截图留作人工审查，布局与主题断言自动执行。
- 不新增用户行为埋点。首次报告耗时、教师建议修改率等真实试点指标需要另行确定采集口径，不能用测试数据当成运营结论。

OpenAPI 生成工具放在 `frontend/app/tools/api-contract` 独立安装：生成器当前依赖 TypeScript 5，不改动应用使用的 TypeScript 6。

## 验证命令

```sh
cd backend
python -m pytest tests simulator -q
python -m scripts.export_job_contract --check
cd ../frontend/app
npm ci
npm ci --prefix tools/api-contract
npm run gen-api
npm run build
npm run lint
npx playwright install chromium
npm run test:e2e
```

可用 `SC_TEST_PYTHON=/absolute/path/to/python` 指定浏览器测试后端解释器。服务器仅绑定 127.0.0.1 的 18000 / 15173 端口，不读取本地 `.env` 或运行数据库。
